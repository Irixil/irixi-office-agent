# Personal Agent 阶段进度与下一步（2026-10-02）

本轮在已有 Irixi 框架继续开发，没有另起产品。最高目标是让用户用 Personal Agent 推进自己的真实项目，更好参与，知道做到哪、还缺什么、下一步做什么。当前阶段的局部验收通过，**不等于整体 Personal Agent 已完成**。

建设纲领的唯一入口是根目录 [AGENTS.md](../../AGENTS.md)，按五个环节组织：接住目标、组织执行、跟踪变化、交付验证、下次继续。目标可以由用户明确改变；讨论不自动替换已确认方向，目标、成功条件和边界一起形成版本。

## 当前能用的部分

目标/版本、显式关联任务、已接受交代、计划、工作项、会话、候选、审阅和指定版本确认保存在同一任务记录。关联根目标或交代变化能使旧计划失效、拒收迟到结果，旧候选不能冒充新版成果。普通任务停止或重启后可以按有效记录继续；不可恢复或达到预算的失败会明确停止。

当前通用工具是材料读取/搜索、已授权已确认记忆搜索、受控计算、公开网页搜索/读取；project 任务另有受限工作区读取、候选写入、固定检查和实际 diff。候选文件可独立核对，指定版本确认后下载。办公室及进度面板来自实际记录，展示已完成、缺口、停下原因和下一步。

“下次继续”的四项是最新确认目标、已确认成果、未解决问题、下一步。它们已有持久记录和派生视图，同一任务网址或浏览器所选任务可恢复；普通运行仍需 Continue。尚不能自动发现所有相关项目、共享全部材料、保证跨会话语义理解或长期无人值守。

资料/文件辅助可以继续使用。新增代码入口只支持登记的 Node 单文件练习项目，不接受任意目录/命令，只交付经检查、审阅及指定版本确认的 patch。尚未接入用户真实项目；产品没有 Git 或任意 shell 工具。

## 验收与修复边界

本轮用现有真实 Codex CLI 在隔离合成记录中验证了：旧目标规划、新版完整目标接受与旧计划失效、重启保留目标、真实材料读取、候选形成、独立模型审阅、指定版本确认及实际 Markdown 下载。正文保留未验证限制，没有人工改稿或伪造审阅通过。该样例未执行真实项目开发。

另以受控模型 fixture 验证本地 HTTP/持久化/传播、迟到旧结果拒收、旧候选确认与导出拒绝、暂停重启、瞬时故障自动重试、永久错误及同错上限停止、普通 Continue 阻塞；DOCX 生成渲染及下载哈希实际核对。规划、合成、语义审阅与故障是模拟，宿主行为和文件是真实。模型故障分支不冒充真实模型现场证据。

修复了终止任务仍提示“恢复未完成步骤”的进度矛盾：现在先展示终止原因与必要处理。未清除停止原因、放开 Continue 或重置预算。已有测试与独立审查通过，未穷尽所有终止状态排列。材料阶段另有实际Chrome表单验收；跨机器环境未验证。

已下载并不意味着产品知道客户端已保存文件；现阶段导出后记录仍可保持 ready_to_export。跨会话总费用账本、跨文件事务、多进程锁和跨执行端迁移尚未实现。模型语义判断及审阅不是确定性业务正确证明。

细节验收、合成任务记录、日志、模型输入、下载产物与本地路径只保留在开发环境，不上传。既有原业务任务字节保持不变。此次仓库同步不是部署。

## 已接入：材料适用性

此前改目标后全部ready材料仍可进入模型，旧批准也不绑定材料集合。本增量让材料用途决定影响实际工具可读范围、模型输入、计划和成果/批准资格。用户保存用途、原因、交付影响与来源正文hash，明确哪些事实可沿用、哪些要求只属于旧目标、哪些约束需重新确认。根材料不默认共享。

事实参考表示用户允许引用来源，不证明整篇文档真实；混合文档仍须拆分。根/独立任务事实可在同一任务且正文不变时跨目标沿用；关联子任务还要求根范围不变。关键待确认约束允许独立材料研究，在合成前停止；非关键排除不扩大成全局停机。决定变化后旧候选、批准和迟到结果保留历史，不能作为当前交付。原件和决定历史仍在既有任务记录，当前UI显示最新用途/原因，尚无完整历史原文查看器。

派生信息也受约束：旧网页证据、研究结果、摘要、输出和引用不能经重规划或historicalCompletedEvidence绕回新工作。生成网页证据绑定当前执行链，不进入规划指纹；URL/hash复用补登记新binding。最终独立审阅按当前候选依赖链取得有效研究结果和真实工具记录，不依赖固定角色名，也不把其他历史会话当作证据。

受控回归验证了范围/正文/决定变化、迟到页面、旧候选和批准拒收、普通Continue研究至合成门槛、linked legacy字节兼容及旧派生正文sentinel排除。主控实际Chrome完成事实用途、关键重确认、非关键排除、目标变化与重载；原任务文件及既有已批准Markdown下载与基线一致。DOCX另以演示正文/审阅实际生成、预览和下载核对hash，并验证材料撤销后拒绝旧批准；该演示预览有文字重叠，只证明文件/资格路径，不作为版式验收。

最终冻结候选的真实现有Codex CLI样例通过：接受新目标与重启恢复后，只读有效事实记录；普通Continue完成独立研究，再停在关键约束确认处，尚无候选。操作者在当前scope确认约束后重新规划、读取、起草与真实独立审阅通过；未经成果确认的下载被拒，指定版本确认后实际Markdown下载成功。撤销材料引用后同一批准被拒，原件及成果/批准历史仍保留。整个样例使用隔离合成记录，不执行笔记工具试用或项目代码；材料和成果确认由验收操作者提交API。

此前真实尝试保留失败：模型合并研究/起草而停在门槛、无效确认工作被DAG拒绝、最终审阅因遗漏动态研究证据退回。最后一项促成候选依赖链证据修复，并用新运行复验；没有手改正文或人工放行审阅。最终运行有2次规划、8次执行调用，真实Token和费用未知。不能称为首次即自动成功或全程无人干预。

没有新增依赖、服务、模型提供方或索引。材料语义用途、文档真实性和混合文档拆分仍需用户判断；已确认记忆只作带来源范围的reference-only线索。历史无制度任务保持兼容，启动/GET不迁移原数据，首次明确写入变更才激活机制。本增量未接通项目工作区读写、项目测试或Git工具。

## 已接入：受限 Codex 项目闭环

保留现有目标版本、显式关联、持久状态、DAG、预算/取消/重启、旧结果守卫、独立审阅、指定版本确认和进度。新增 project/project_patch、四项结构化 workspace 工具，以及授权与 diff/check 页面；没有新增依赖、模型提供方、账户、凭据或外部服务。

本次真实流程只处理登记的合成 Node 单文件项目：接受完整新目标、保存并重启；旧授权失效且迟到点击被拒；实际 Chrome 按新版本授权并重载。现有真实 Codex CLI 随后实际读取 src/greeting.mjs、按当前 hash 写入候选、运行固定三组契约检查、生成非空真实 diff；宿主据此生成 patch，独立 Codex 审阅通过。宿主在汇总前直接提供三文件授权时与当前original/task source的真实hash/bytes核对证据，在审阅、确认、下载前重新实读核验；证据绑定成果指纹，不能由模型文字代替。最终审阅同时收到当前候选绑定的完整计划授权及实际 read→write→第三批 check+diff 宿主审计，合成、审阅、交付授权均为空；核对前重新从当前执行链生成同一摘要，篡改或过期则拒绝。未确认下载被拒，Chrome 确认指定版本并实际保存 patch，浏览器与 API 下载 hash 均等于已审阅候选。

确认及交付后重启服务，批准仍保留；再接受“只评估，不交付修复”的新目标后，旧成果重复确认与同一旧批准下载均被拒，Chrome 重载不再提供旧成果链接，旧候选与批准保留历史。原三文件和冻结应用文件逐字节不变。候选没有应用到原目录，也没有执行 Git/发布。下载共 251 字节，SHA-256 `4eff538b46441bedc683fa1c1796f1e432b30b77f9badb5e390c5d108d20ceac`。

本次由两个有边界的真实阶段组成：第六次运行有一次真实规划、6 次执行调用及一次最终独立审核，共8份CLI请求；工具与语义审核通过，但宿主把真实检查和diff计数当成无原文依据数字而拒绝，其重规划请求在提交前被拒绝。随后只修复当前候选绑定的宿主计数依据，保持业务数字守卫，先重放原正文与确认/下载/目标变更门；原候选与固定检查通过新冻结版物理及审计核验后，通过正常复审接口追加 1 次真实独立审核。复用阶段调用前守卫仅允许review、最多一次、10分钟，禁止规划/重规划/执行和工具；旧失败审核及请求逐字保留。两阶段合计9次CLI提供者调用；这些不是网络推理请求数或Token统计，实际费用和Token未测，没有手改审核结论或传入模型结果替身。之前真实失败保留：目标变化后授权绑定缺失、运行重建会话缺失工作区绑定，均做定向修复并复验；另一次规划把 check/diff 重复分配给审阅而被守卫拒绝。第四次真实流程因为三文件证据缺少公开传递触发重规划，最终语义审阅在验收观察器检测第11执行槽时被取消；该旧观察器是调用后的取消，并非调用前硬上限。第五次真实流程已经通过三文件与候选检查，但最终独立审阅未拿到候选对应的计划授权和工具批次记录；其重规划请求被调用前预算守卫拒绝。本轮先补齐与成果绑定的完整执行审计，随后为检查用例与diff变更数增加按语义位置验证的宿主事实；交换主体、虚构计数、模型自称依据、旧goal/candidate与业务金额仍拒绝。最终成功复用合法旧候选，并另经真实复审、确认、下载及目标变化验证；没有手改候选、手造计划或人工放行审核，不称为首次即成功或全程无操作者参与。

确定性宿主边界另以受控提供者/实际本地 HTTP 和原生隔离检查验证；这些局部测试不冒充真实模型现场。原任务兼容性在隔离拷贝中检查，38 份既有任务文件与一份已批准 Markdown 下载保持字节/hash一致。全套回归在授权修复版通过，后续会话、来源完整性及执行审计修复只重验受影响的宿主与 HTTP 路径，其中受控模型和实际固定检查直接检验完整最终审阅输入；未宣称最终文件全套重新运行。

权限范围只有登记 fixture、两个可读文件和一个可写候选文件；固定父侧契约、原生隔离与指纹守卫不可由模型替换，能力不可用时停止。三组固定 case 不证明全部输入正确，原生隔离限本机 macOS；仍需用户明确目标取舍、作用域授权和指定成果确认。自动发现相关项目、任意项目接入、任意 shell/测试/Git、自动应用、跨会话费用总账、多平台切换和长期无人值守仍未完成。

下一步只选用户明确指定的一个低风险真实项目小改动，登记所需文件和固定检查，并以其实际业务结果验收。收益是把本次受限练习流程用到一个真实项目；不先搭通用平台或扩大权限。

复用现有 Codex CLI、Node 标准库和 macOS 原生隔离；参考 OpenAI 官方 [Seatbelt 实现](https://github.com/openai/codex/blob/main/codex-rs/sandboxing/src/seatbelt.rs)、[基础策略](https://github.com/openai/codex/blob/main/codex-rs/sandboxing/src/seatbelt_base_policy.sbpl)与[Apache-2.0 许可证](https://github.com/openai/codex/blob/main/LICENSE)。没有复制上游代码或接入新 SDK；Node 自身权限模型未被当成恶意代码隔离边界。星数不证明可信度、收益或省 Token，尚无 Token 节省比例。
