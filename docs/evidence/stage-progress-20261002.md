# Personal Agent 阶段进度与下一步（2026-10-02）

本轮在已有 Irixi 框架继续开发，没有另起产品。最高目标是让用户用 Personal Agent 推进自己的真实项目，更好参与，知道做到哪、还缺什么、下一步做什么。当前阶段的局部验收通过，**不等于整体 Personal Agent 已完成**。

建设纲领的唯一入口是根目录 [AGENTS.md](../../AGENTS.md)，按五个环节组织：接住目标、组织执行、跟踪变化、交付验证、下次继续。目标可以由用户明确改变；讨论不自动替换已确认方向，目标、成功条件和边界一起形成版本。

## 当前能用的部分

目标/版本、显式关联任务、已接受交代、计划、工作项、会话、候选、审阅和指定版本确认保存在同一任务记录。关联根目标或交代变化能使旧计划失效、拒收迟到结果，旧候选不能冒充新版成果。普通任务停止或重启后可以按有效记录继续；不可恢复或达到预算的失败会明确停止。

当前工具是材料读取/搜索、已授权已确认记忆搜索、受控计算、公开网页搜索/读取。候选文件可独立核对，指定版本确认后下载。办公室及进度面板来自实际记录，展示已完成、缺口、停下原因和下一步。

“下次继续”的四项是最新确认目标、已确认成果、未解决问题、下一步。它们已有持久记录和派生视图，同一任务网址或浏览器所选任务可恢复；普通运行仍需 Continue。尚不能自动发现所有相关项目、共享全部材料、保证跨会话语义理解或长期无人值守。

当前实现偏向资料/文件辅助；没有项目工作区读写、项目测试、Git 或任意 shell 工具。Codex 帮我们开发 Irixi，不等于 Irixi 已能用 Codex 替用户开发真实项目。

## 验收与修复边界

本轮用现有真实 Codex CLI 在隔离合成记录中验证了：旧目标规划、新根目标接受与旧计划失效、重启保留目标、真实材料读取、候选形成、独立模型审阅、指定版本确认及实际 Markdown 下载。正文保留未验证限制，没有人工改稿或伪造审阅通过。该样例未执行真实项目开发。

另以受控模型 fixture 验证本地 HTTP/持久化/传播、迟到旧结果拒收、旧候选确认与导出拒绝、暂停重启、瞬时故障自动重试、永久错误及同错上限停止、普通 Continue 阻塞；DOCX 生成渲染及下载哈希实际核对。规划、合成、语义审阅与故障是模拟，宿主行为和文件是真实。模型故障分支不冒充真实模型现场证据。

修复了终止任务仍提示“恢复未完成步骤”的进度矛盾：现在先展示终止原因与必要处理。未清除停止原因、放开 Continue 或重置预算。已有测试与独立审查通过，未穷尽所有终止状态排列；本轮未重跑真实浏览器或跨机器环境。

已下载并不意味着产品知道客户端已保存文件；现阶段导出后记录仍可保持 ready_to_export。跨会话总费用账本、跨文件事务、多进程锁和跨执行端迁移尚未实现。模型语义判断及审阅不是确定性业务正确证明。

细节验收、合成任务记录、日志、模型输入、下载产物与本地路径只保留在开发环境，不上传。既有原业务任务字节保持不变。此次仓库同步不是部署。

## 优先做一项：材料适用性

目标版本已约束计划与成果，但材料尚未按目标适用性隔离；任务全部 ready 材料仍可进入模型，成果/批准也不绑定材料集合。输入边界应先补齐，再扩展项目编辑权限。

保留原件和历史，分别记录可复用事实、旧目标专属材料、待重新确认约束。事实保留来源和验证资格；旧目标材料保留历史；未确认约束不擅自沿用或扩大权限。决定应影响实际工具可读范围、计划输入、成果/审阅/确认的新鲜度，而不只改提示词。根材料不默认共享。

成功条件：一次真实目标变化后，事实可继续引用、旧要求不进入当前执行、待确认约束只阻止受影响动作、历史可回看；适用性改变能拒收在途旧输出，回来后能直接看到保留/停用/待确认原因和下一步。当前只用明确已接受交代和人工候选核对减险；硬机制本轮未实现。

## 保留框架，接入最小 Codex 项目闭环

保留目标版本、任务关联、持久记录、依赖、预算/取消/重启、旧结果守卫、确认链及进度界面；资料/Office能力继续作为辅助。

要改造的现状：计划成果枚举限于办公/研究类型，执行工具限六项，流程要求合成→独立审阅→文件交付；当前 Codex 关闭原生操作，在独立目录返回结构化结果。需要新增受限项目执行入口与补丁/检查成果契约，避免把代码变更装进文档。已有提供者直接分支 Codex CLI/演示，不是任意平台可切换的适配层。

先选择用户真实项目的一处低风险小改动，定义业务成功标准与以下权限：

| 能力 | 最小范围 |
|---|---|
| 读取 | 一个固定工作区和允许文件；读取当地规则，核对当前基线及未提交变更，禁止越界 |
| 编辑 | 隔离候选/分支、约定文件、内容基线检查；保留用户并发修改 |
| 检查 | 固定 cwd、程序、参数、时限的测试/检查；真实退出码和日志；不提供任意 shell |
| 差异与应用 | 可查看 diff、证据、指定版本授权、应用前再核基线和备份；Git已有就复用，不自动 commit/push/删除 |

验收看真实项目工作推进和参与体验：产生可查看的真实变更、实际检查结果、中途换目标能停旧变更、失败有限处理、用户看懂缺口并只决定必要问题、退出后不用重复交代已保存信息。此闭环本轮尚未接入或运行。

模型提供方负责推理；Codex/Claude Code等执行平台负责授权项目动作；Harness保存权限、目标、状态、预算和交付；判断模块辅助对齐/审阅。先跑通Codex一个闭环，再逐项比较其他平台、模型与新能力。记录应能迁移，不承诺切换零成本；现在不搭通用多平台框架、不接新服务或凭据。

可信复用候选是 OpenAI 官方 [Codex TypeScript SDK](https://github.com/openai/codex/blob/main/sdk/typescript/README.md)，其 CLI 封装、流事件和线程续接可能减少协议适配工作。主分支[包清单](https://github.com/openai/codex/blob/main/sdk/typescript/package.json)标示 Apache-2.0、Node>=18、0.0.0-dev；[根许可证](https://github.com/openai/codex/blob/main/LICENSE)可核对。维护频率、本机协议/权限/取消兼容性、固定发行依赖和许可适配仍待核，未下载或安装，不能直接据此接入。优先复用现有CLI并隔离比较一个场景，无收益则不新增依赖，保留回退。Star不是可信度或Token节省证明；MiniSearch此前无收益而保留原生方案的决策不变。
