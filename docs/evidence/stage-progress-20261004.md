# Personal Agent 阶段进度（2026-10-04）

这一阶段把代码项目从两个固定演示扩到一个仍然有界的自然语言入口。用户可以先描述目的，Irixi 根据登记仓库的真实结构整理需求、交付物、成功条件、边界、有限文件和固定用例；需求卡与逐例预期必须明确接受，工作区再单独授权。产品没有因此获得任意目录、shell、Git 或自由测试命令。

## 实际业务结果

真实任务选择了 Irixi 导航同步中的一个低风险纯函数改动。产品读取一个可修改模块和一个只读调用方，生成 628 字节候选文件；原生语法检查 1/1、JSON 行为检查 6/6 通过，候选只改一个获准文件。工作审阅和最终独立审阅均由真实 Codex 完成并通过；审阅明确保留“有限调用方片段不能证明所有链接入口”的非阻断限制，没有把局部证据扩大为完整调用图。

用户明确授权后，真实 Chrome 在独立 profile 中打开正确目标与通俗进度，原生点击确认指定 v1，并实际下载 1150 字节、SHA-256 `533f7956cc9d1ba8a6c5e84b29982b886bad1f16f50a92b285c7d68788b7046a` 的同一份已审 patch。关闭浏览器后以同一 profile 重开，任务仍可续接；随后通过页面原生填写并接受新版完整目标，再打开旧批准下载链接时产品返回 HTTP 400，且没有产生新下载。整个浏览器流程没有用 API 调用代替点击，也没有新增产品模型调用。

真实模型调用按阶段累计账本记账，失败与复审没有退款或重置。最初 9 次调用耗尽后，统一证据机制先只用受控替身和本机检查修复、回放；用户随后另行明确授权仅 2 次真实审阅，工作审阅和最终独立审阅均通过，阶段累计为 11 次。此后的浏览器、安装和仓库验收没有再调用产品模型。受控回放证明传给两层审阅的实际序列化输入含相同权威证据基础，并验证缺接受凭据、旧目标、旧来源、越权文件、错误候选、错误数量或错误检查时会在调用前停止；受控通过不冒充新的真实语义审阅。

## 通用入口

当前入口只登记 Irixi 自身源码根，并限于无 import 的同步 JS/MJS 纯函数：最多读取 8 个文件、修改 2 个文件、选择 3 项固定检查。JSON 行为检查的输入与预期由用户在需求卡中逐项接受；syntax-only 不能成为业务验收。模型不能提供命令、工作目录、环境变量、包装器或测试代码。

执行由宿主管理为一次事务：只读来源快照 → 有界真实读取 → 一个候选修改批次 → 全量 CAS → 任务私有候选原子发布 → 固定检查 → diff。失败保留候选与诊断并停止，不暗中重复 owner、不自动重规划。原源码始终只读，正式结果仍是 patch 下载，不自动应用到仓库。

## 统一审阅证据链

本阶段新增一个共享审阅证据包。它由当前宿主状态重建，包含：

- 已接受的目标、成功条件、边界、逐例用例、范围与授权事件；
- 来源树、可读/可改清单、来源和候选 manifest，以及有界调用方片段；
- 候选语义摘要、实际 patch/diff、固定检查、执行 actor/顺序和来源权限；
- 工作审阅回执与最终审阅所需的运行、会话、工作项及摘要绑定。

工作审阅和最终审阅使用同一权威基础；最终审阅还必须带同一次审阅运行保存的工作审阅回执。发送模型前、写入审阅、指定版本确认和导出都会重新核对证据包、候选语义和工作审阅摘要。模型返回的自述、旧 packet 或调用方传入的 hash 不能替代当前物理状态。

关键数字只在明确引用当前固定检查、当前候选和正确主体时才可进入成果；同值但主体无关、错误检查、歧义句或过期证据会失败。这个守卫证明来源绑定，不替代独立语义审阅。

## 还缺什么

当前证据只覆盖登记的 Irixi 仓库、同步纯函数、有限文件和固定 JSON 用例。它不支持任意仓库、import 依赖闭包、多包构建、自由命令、任意测试框架、shell、Git 自动提交、自动安装或发布，也没有证明长期无人值守、跨平台隔离和所有调用入口覆盖。继续扩大前仍需具体目标、范围、固定检查和新的明确授权。
