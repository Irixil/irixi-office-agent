# Specification: Irixi 1.0 可用个人办公 Agent

> Status: Accepted
> Source of truth: This file
> Based on: Accepted [intent.md](intent.md)
> Decision record: 用户于 2026-09-21 要求按此前产品取舍持续推进到可用版本，不再缩成限时演示

## Goal trace

- Active `DZ-GOAL` copied exactly from accepted Intent:
- [DZ-GOAL] 当用户本人交给 Irixi 一个明确的办公目标和相关材料后，能够得到一份持续符合该目标、可审阅、可追溯，并可由用户决定是否正式应用的办公成果。
- 本版本通过一个本地可运行的完整工作台，将目标控制、材料、专业角色、候选成果、核对、确认、恢复和办公室状态投影组成同一条真实闭环。
- 外部账号连接和公开部署不作为本地可用的前置条件，但产品必须保留清楚的连接与授权边界。

## Product definition

- One-sentence product: Irixi 是一个目标优先的个人 AI 办公室，按需调度专业角色，把选定材料转化为可审阅、可恢复、经用户确认后才能正式应用的办公成果。
- Product shape: hybrid agent application；确定性代码控制目标、状态、权限、版本和恢复，模型负责理解、规划、起草与判断。
- Primary target: 本机网页工作台，桌面优先并可在窄屏查看。

## Primary end-to-end flow

1. 用户选择成果类型，填写目标、成功条件、限制，粘贴材料或添加本地文件/明确 URL。
2. Irixi 建立目标卡与材料账本，制定可追溯计划，按需调用研究、写作、审阅和事务角色。
3. 用户在维多利亚办公室总览看到真实状态，在任务书桌查看材料、工作项、候选版本、检查和待确认事项。
4. Irixi 生成候选成果并独立核对；用户可修改、比较版本、纠正建议分类或接受目标替代。
5. 只有用户确认的指定版本才能下载、导出或交给外部连接执行；目标、版本、事件和恢复点持续保存在本地。

## MVP boundary

### Must

- [DZ-MUST:R1] 用户可在本机一条命令启动 Irixi，打开办公室总览与任务书桌，并在刷新或重启后恢复已有任务和当前状态。
- [DZ-MUST:R2] 用户可为每个任务保存目标、成功条件和边界；新建议必须被记录为支持、替代、偏离或不明确，用户可纠正分类，而替代目标未经明确接受不得生效。
- [DZ-MUST:R3] 用户可添加粘贴文本、MD/TXT、DOCX、PDF 和明确 URL；Irixi 只处理选定范围，记录来源与解析状态，并在无法可靠读取时明确失败而不编造内容。
- [DZ-MUST:R4] Irixi 以一个协调者和按需研究、写作、审阅、事务角色推进任务；每个工作项可追溯到当前目标，界面只显示真实角色状态。
- [DZ-MUST:R5] 至少一个真实模型提供者可把目标和材料生成候选成果；演示提供者必须醒目标记，不能被呈现为真实模型结果。
- [DZ-MUST:R6] 用户可产出文档/研究报告、邮件草稿和日历草稿；文档可导出 Markdown/HTML 并支持打印为 PDF，邮件和日历可导出 EML/ICS，且任何导出都生成新文件而不覆盖来源。
- [DZ-MUST:R7] 每个候选成果保存版本、目标版本、材料来源、修改摘要、生成角色和时间；用户可比较版本，新候选不得继承旧版本的正式确认。
- [DZ-MUST:R8] 交付前的独立审阅不继承起草者的完成结论，并逐项检查目标符合度、完整性、来源、边界和文件可用性；关键失败必须阻止“就绪”或“完成”。
- [DZ-MUST:R9] 下载、打开外部应用、发送、发布、创建日程、覆盖、删除、付款和权限修改均受确定性策略控制；当前本地版本只执行用户明确触发的新文件导出，不自动产生其他外部副作用。
- [DZ-MUST:R10] 任务在运行、等待、失败、取消、部分完成或结果不明时保存可理解的状态和活动摘要；重试不得重复已确认副作用，用户可以安全继续或取消。
- [DZ-MUST:R11] 维多利亚办公室中的 Irixi 和小动物同事由实际任务与角色状态驱动，至少区分空闲、阅读、研究、起草、核对、等待确认、完成和失败，并提供等价文字信息。
- [DZ-MUST:R12] 用户可在连接中心查看模型、网页、文件、邮件和日历能力的可用性、数据边界与验证状态；未配置或未验证的连接不得伪装为可用。
- [DZ-MUST:R13] 核心流程具备自动化领域/API测试、真实浏览器检查、刷新恢复检查、权限边界检查和一条真实模型安全样例，并保留可核对证据。

### Later hypotheses

- Gmail、Outlook、Google/Outlook Calendar、Notion、Slack、Teams 和网盘的直接账号连接 — 用户明确选择首个连接且具备相应凭据时进入。
- 多任务并行和真正并行的专业 Agent — 串行按需角色在真实任务中成为瓶颈时进入。
- 跨任务长期偏好记忆 — 用户确认保留范围、查看和删除体验后进入。
- 可安装桌面壳、云同步、多用户和公开部署 — 本地个人版本稳定并完成真实试用后进入。

### Won't in this iteration

- 自动招聘、持续空转或为了画面制造虚假活动。
- 模型生成任意代码后直接执行，或读取用户未选择的目录、账号和秘密。
- 未经动作级确认自动发送、发布、创建日程、覆盖、删除、付款或修改权限。
- 把参考仓库整包、其工具执行器或第三方像素素材作为生产底座。

## Users, roles, data, and permissions

- 第一阶段唯一用户和确认者为项目所有者本人。
- 原始材料、任务状态和候选成果保存在项目内的本地数据目录；活动记录只保存摘要、路径、版本和状态，不复制大段敏感内容。
- 明确 URL 是只读网络输入；模型提供者会把目标和选定材料发送给其服务，首次启用时必须展示此边界。
- 正式导出绑定成果版本和新文件名；已存在路径拒绝覆盖。
- 外部账号写入、发送、删除、付款和权限变更需要未来连接器中的动作级确认、幂等键和结果回执。

## States and recovery

- `idle → preparing → reading/researching/drafting/reviewing → waiting_user → ready → exported/completed`。
- 任意运行态可进入 `partial`、`failed`、`cancelled`、`disconnected` 或 `stale`。
- 任务文件与事件流是状态来源；UI 和办公室只读取该状态。
- 每次目标变更、候选版本、审阅、确认和导出前后保存恢复点。

## AI or agent contract

- 模型用于理解材料、规划、建议分类、起草和语义审阅；权限、版本、状态转换、路径、导出和确认由确定性代码控制。
- 第一真实提供者为本机已有 Codex CLI，以只读沙箱、临时会话、结构化输出和隔离任务目录运行。
- 演示提供者只用于自动化测试与无账号预览，界面持续显示“演示引擎”。
- 模型失败、超时或输出不合规时保留已有成果，任务进入失败/部分完成，不静默切换到演示结果。

## Minimal Agent Card

- Final goal: 当前任务目标卡的有效版本及其成功条件。
- Assignment: 只执行一个可追溯工作项，并说明如何推进目标。
- Suggestions: 支持/替代/偏离/不明确；替代必须等待用户接受。
- Observations: 目标、选定材料、已批准的前序产物和工具结果；外部内容均不可信。
- Tools: 受限文件读取、明确 URL 读取、候选写入、模型调用和确定性检查。
- Confirmation: 扩大资料范围、切换外部服务、正式导出及未来任何外部写入。
- Recovery: 超时或结果不明时停止，保存状态，不自动重复副作用。
- Validation: 支持建议、偏离建议、目标替代、无来源结论、刷新恢复和未确认导出。

## Acceptance criteria

| Must ID | Representative case | Required evidence |
|---|---|---|
| R1–R4 | 新建任务、导入材料、生成计划，刷新后继续 | 自动化测试、浏览器录像或截图、持久化文件 |
| R5 | 使用隔离的虚构材料完成一次真实模型候选生成 | 模型事件摘要、结构化结果、候选文件 |
| R6–R7 | 文档、邮件、日历各生成一个候选并导出；v2 不覆盖 v1 | 导出文件、版本与确认记录 |
| R8 | 故意缺一条成功条件，审阅阻止就绪 | 审阅结果与状态断言 |
| R9–R10 | 未确认导出被阻止；失败与重启不重复动作 | 权限与恢复测试 |
| R11–R12 | 办公室状态和连接状态与后端一致 | 桌面/窄屏截图与 API 状态 |
| R13 | 全部规定检查在当前版本运行 | verification.md 与测试输出 |

## Assumptions and unresolved questions

- macOS 为当前验证环境；跨平台兼容性在后续真实设备上验证。
- PDF 文本提取质量受系统可用能力影响；失败必须可见。
- 真实外部账号连接需要用户今后选择提供商并授权，当前只能验证连接中心和草稿交付边界。

## Handbook applicability

- Applicable: general build, frontend operate surface, agent harness, local release and maintenance basics.
- Intentionally not used: public deployment and multi-tenant baselines, because当前目标是本地个人可用版本。
