# Irixi 办公 Agent：产品意图

> 状态：Accepted
> 来源：本轮产品讨论与两个参考项目的只读分析
> 决策记录：用户于 2026-09-21 明确要求取消时间限制，按此前取舍持续推进，将两个参考办公 Agent 的可取思想融合到一个可用版本

## 用户原话中已经明确的方向

- 新项目叫 Irixi，是一个办公 Agent。
- 第一阶段只服务用户本人。
- 借鉴 OpenOffice 与 agent-office 的想法和少量合适部分，不与原项目共创，也不整套照搬。
- 采用类似 DZ 的连续工作架构，但必须修正容易被新建议带偏的问题。
- 最终目标高于临时建议、技术方案、功能清单和当前步骤。
- 重要结果先形成可审阅版本；覆盖原文件、发送、发布或其他有外部影响的动作，需在用户确认后进行。
- 维多利亚时代猫头鹰绅士与办公室是产品的视觉表达，具体美术在独立任务中继续。

## 主要用户与触发场景

- 主要用户：第一阶段仅为项目所有者本人。
- 触发时刻：用户交给 Irixi 一个办公目标、相关材料和必要限制，希望它持续把事情做完，而不只是回答一轮问题。
- 用户、购买者和最终确认者：第一阶段为同一人。

## 问题与当前做法

- 已确认的问题：长任务中，Agent 容易被后来出现的新建议、局部问题或更容易完成的替代结果带偏。
- 可能存在但尚未确认的问题：办公材料分散在聊天、文件和不同工具里，用户需要反复说明目标、检查版本和手动衔接步骤。
- 当前做法及其代价：尚待用一个真实办公任务补充，不能把推测当成已经验证的事实。

## 最终目标

- [DZ-GOAL] 当用户本人交给 Irixi 一个明确的办公目标和相关材料后，能够得到一份持续符合该目标、可审阅、可追溯，并可由用户决定是否正式应用的办公成果。
- 达成条件：在一个真实的端到端办公任务中，Irixi 能保存原始目标，把后续建议标为支持、替代、偏离或尚不明确；所有执行步骤都能追溯到目标；最终成果经过对应检查；有外部影响的动作只在用户确认的范围内发生。
- 初期成功信号：用户不需要反复纠正方向；能看懂当前目标、当前产物、未完成项和下一步；候选版本与正式版本不会混淆。

## 当前判断

- 已决定继续，并以“材料到可审阅办公成果”作为第一条真实闭环；文档、研究简报、邮件草稿和日历草稿共享同一目标、版本、核对和确认机制。
- OpenOffice 与 agent-office 更适合作为产品模式、状态可视化和少量接口设计的参考；执行、权限、目标控制和验收闭环由 Irixi 自己实现。
- 第一版先在用户本机运行。完整外部账号连接需要相应凭据和动作授权，但不能阻止本地可用版本形成。

## 约束

- 第一阶段单用户、本地优先、低权限起步。
- 读取、分析、整理和生成候选稿可以在授权范围内连续进行。
- 覆盖原文件、发送邮件或消息、发布、删除、付款、改权限及其他难以撤销的动作必须有动作级确认和结果回执。
- 目标变更必须展示旧目标与新目标；只有明确确认的新版本才成为当前目标。
- 安全、法律、第三方权利、平台限制和真实证据可以阻止路线或促成目标重议，但不能把未达成的目标悄悄改成一个更容易完成的结果。
- 复用第三方代码或素材前，单独核对来源、许可、维护状态、安全边界和退出方案。

## 假设与待确认问题

- 假设：用户希望看到办公室与角色的工作状态，但视觉层不应驱动或伪造执行状态。
- 已采用的可逆假设：主要入口为本机网页工作台，后续可包装为桌面应用。
- 已采用的可逆假设：首批资料源为粘贴文本、用户选择的本地文件和明确 URL；外部账号只在连接后使用。
- 仍待真实使用验证：用户最常用的第二类办公成果，以及各动物角色与专业能力的长期映射。

## 停止或收窄条件

- 第一条真实任务无法定义可观察的好结果。
- Irixi 只能增加观看和维护成本，不能减少用户的衔接、校对或重复说明。
- 为了完成首个任务必须提前获得过宽权限，且没有更窄、更可恢复的方案。

## 明确不在第一阶段做

- 多用户、组织权限、团队采购与计费。
- 为了显得热闹而持续空转的 Agent 团队。
- 未经确认自动覆盖正式文件、替用户发送或公开发布。
- 把参考项目整仓作为生产执行底座。
- 用办公室动画或“任务已完成”文案代替真实产物和验证证据。
