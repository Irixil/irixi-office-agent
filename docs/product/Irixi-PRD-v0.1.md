## 1. 决策标记

- **已确认**：来自用户明确表达或已锁定的项目文件。
- **推荐默认值**：根据成功概率给出的首版选择，尚待用户确认。
- **以后再看**：有价值，但不进入首版承诺。
- **开放问题**：会实质影响首版范围，需要在开工前确认。

## 2. 产品摘要

### 2.1 一句话定义

**Irixi 是一个目标锁定的个人办公成果工作台。用户给出明确目标和有限范围的材料后，它会跨步骤、跨会话持续推进，生成可审阅、可追溯的候选成果，并且只有用户明确确认的指定版本才能成为正式成果。**

### 2.2 第一阶段产品形态

第一阶段不做“万能 AI 公司”，而做一条足够窄但完整的闭环：

> **材料与脑暴 → 目标卡 → 可检查计划 → 候选文档 → 独立核对 → 用户修改或确认 → 正式文件**

首个切入口采用“材料到可交付文档”。PRD、方案、研究简报和项目说明都属于这类任务。本次 Irixi PRD 可作为未来系统的首个回放测试夹具，但它由产品出现前的 Codex 生成，不能充当 Irixi 已经完成真实任务的证据。

### 2.3 产品不是什么

- 不是只回答一轮问题的聊天机器人。
- 不是为了好看而让一群 Agent 持续空转的办公室模拟器。
- 不是能随意扫描电脑、执行任意代码或替用户自动对外操作的高权限助手。
- 不是 OpenOffice 或 agent-office 的整仓复制品。
- 不是第一版就覆盖文档、邮件、日历、表格、演示、知识库和团队协作的通用平台。

## 3. 为什么这条路线更可能成功

1. **任务真实且高频**：用户已经在用脑暴、资料和对话产出 PRD 及方案文档。
2. **结果容易验收**：文档是否符合目标、是否缺项、是否引用了材料，可以直接检查。
3. **权限要求较低**：首版只需读取明确选择的资料，在隔离空间生成候选文件。
4. **能验证核心差异**：防跑偏、连续推进、版本审阅、证据与确认都能在一条闭环中被验证。
5. **扩展路径自然**：文档闭环可靠后，再增加 Word、PDF、表格、邮件和日历，不需要推翻核心架构。
6. **可准备真实试用**：当前 PRD、后续技术方案和项目计划可以整理成回放夹具；产品可用后仍须由 Irixi 重新执行真实任务，才能形成有效证据。

## 4. 背景与参考项目取舍

### 4.1 借鉴的产品思想

从 [OpenOffice](https://github.com/longyangxi/OpenOffice) 与 [agent-office](https://github.com/harishkotra/agent-office) 中重点借鉴：

- 一个负责人统筹目标，按需调用专业角色。
- 任务、角色、进度、等待和产物可以被用户看见。
- 办公室场景让抽象的 Agent 状态更直观。
- 工作持续保存，用户回来后可以继续。
- 适配器和事件模型与具体模型、工具解耦。

### 4.2 明确不继承的部分

- 自动招聘或自行扩大 Agent 数量。
- 固定频率自主思考、为了画面而持续活动。
- 由模型生成并直接执行任意代码或 shell 命令。
- 未经确认自动覆盖、合并、发送、发布或删除。
- 用“角色正在工作”或“工作项已完成”代替真实成果验收。
- 把参考仓库的房间运行时、工具执行器或完整架构直接作为生产底座。

### 4.3 复用原则

首选“借模式、重写边界”。任何具体代码、素材或依赖只有在完成来源、许可、安全、维护状态、测试覆盖和退出方案检查后，才能进入复用候选清单。原创 Irixi 视觉资产独立维护。

## 5. 用户与核心问题

### 5.1 目标用户

- **已确认**：第一阶段只有项目所有者本人。
- 使用者、购买者、资料授权者和最终确认者在第一阶段是同一人。
- 暂不设计团队协作、组织权限、计费和租户隔离体验。

### 5.2 触发场景

用户交给 Irixi：

- 一个想最终得到什么的目标；
- 一组聊天记录、脑暴、文件或明确网址；
- 必要的范围、语气、格式、截止时间或禁区；
- 希望 Irixi 持续做到可交付，而不是只给一次建议。

### 5.3 已确认问题

长任务中，Agent 容易被后来的新建议、局部问题或更容易完成的替代结果带偏。用户需要反复提醒原目标，最终仍可能拿到“看似做了很多，但不是要的结果”。

### 5.4 待验证问题

- 材料散落在聊天、文件和网页中，用户是否因此反复搬运和解释。
- 版本、检查、修改和导出是否占用了过多人工衔接时间。
- 用户是否需要通过办公室视图快速理解状态，而不必阅读技术日志。

这些是合理假设，不在真实任务验证前写成已证实事实。

## 6. 最终目标与成功条件

### 6.1 当前目标锚点

> 当用户本人交给 Irixi 一个明确的办公目标和相关材料后，能够得到一份持续符合该目标、可审阅、可追溯，并可由用户决定是否正式应用的办公成果。

该目标目前来自 `docs/sdlc/intent.md` 的 Draft，尚待用户正式接受。

### 6.2 达成条件

在一个真实的端到端办公任务中：

1. 原始目标和达成条件被结构化保存，不只存在于聊天上下文。
2. 后续建议被识别为支持、替代、偏离或不明确。
3. 所有工作项、动作、产物与证据都能追溯到当前目标版本。
4. 候选成果经过与目标相匹配的检查。
5. 候选版本与正式版本不会混淆。
6. 任何覆盖、发送、发布、删除等正式动作只在用户确认的准确范围内发生。
7. 中断后能够恢复正确目标、当前成果、未完成项和待确认事项。

### 6.3 首版北极星

**用户是否能更少地重复说明和纠偏，拿到一份自己愿意确认使用的成果。**

角色数量、动画丰富度、模型调用次数和“忙碌时长”都不是北极星指标。

## 7. 产品原则

1. **最终目标优先**：目标高于最新消息、局部建议、技术方案和当前步骤。
2. **目标可以改，但不能暗改**：替代目标必须展示旧版、新版和影响，并由用户明确接受。
3. **真实状态优先**：界面、角色动作和进度只投影真实运行状态。
4. **候选与正式分离**：默认生成新版本，不直接覆盖来源或已确认成果。
5. **连续工作，关键边界确认**：低风险候选空间内可连续推进，跨越正式或外部边界时再确认。
6. **证据先于完成声明**：做完一个步骤不等于目标达成；完成必须绑定检查结果。
7. **一个负责人，按需协作**：Irixi 对最终结果负责，专业能力按任务需要出现。
8. **最小资料与最小权限**：只读取本任务明确授权的材料，只给予完成当前动作所需的能力。
9. **失败可见、可以恢复**：失败、超时、不确定和部分完成必须如实显示。
10. **产品核心与视觉解耦**：视觉增强理解和情感连接，但不决定执行逻辑。

## 8. 第一阶段范围

### 8.1 Must：个人版 MVP 必须完成

- 创建一个材料到文档的任务，并生成可见目标卡。
- 保存一个当前活动目标版本；目标不能被模型或专业角色静默修改。
- 读取用户粘贴的文本及明确选择的 Markdown/TXT 材料。
- 生成与目标绑定的短计划和可检查工作项。
- 由一个协调者按需调用资料整理、写作和审阅能力。
- 产出 Markdown 候选文档，保留版本、来源、变更摘要和检查结果。
- 支持用户提出修改、比较版本、确认准确版本并导出为正式文件。
- 在应用关闭或任务中断后恢复目标、材料索引、进度、候选版本和待确认事项。
- 对失败、取消、超时和结果不明确提供真实状态与安全恢复路径。
- 提供一个最小的 Irixi 真实状态指示，不建设完整办公室场景。
- 保存用户可读的活动记录，不展示或依赖模型隐藏思维。

### 8.2 推荐默认输入与输出

| 类型 | 首版建议 |
|---|---|
| 直接输入 | 对话与粘贴文本 |
| 本地材料 | Markdown、TXT，只读导入；解析失败时明确提示 |
| 网络材料 | v0.1 不直接读取；需要时由用户提供选定内容或本地快照 |
| 候选成果 | Markdown，保存在 Irixi 任务工作区 |
| 正式成果 | 用户确认准确版本后，导出一个新的 Markdown 文件 |
| PDF、DOCX、网页与高保真导出 | v0.2 候选，不阻塞首个闭环 |

### 8.3 Later：有触发证据后再进入

- PDF、DOCX 和明确 URL 的只读导入，以及 Word、PDF、表格和演示文稿的高保真编辑与导出。
- 邮箱、日历、Notion、网盘、Slack、Teams 等连接。
- 多任务并行和真正并行的专业 Agent。
- 本地模型、多模型选择和自动模型路由。
- 经用户确认的跨任务长期记忆和语义检索。
- 定时任务、无人值守监控和远程控制。
- 完整办公室建筑、多位小动物同事、房间装修、角色行走、布局编辑和更多互动。
- 多用户、团队权限、云同步、计费与公共发布。

Later 只是候选方向。只有真实使用暴露出明确需求，才进入当前版本。

### 8.4 Won't：首版明确不做

- 自动招聘、自动扩张 Agent 团队或自主改变组织结构。
- 多个 Agent 为了表现活跃而持续空转。
- 覆盖已有文件，以及发送、发布、删除来源或外部内容、付款、创建日程、修改权限。
- 任意代码执行、扫描整台电脑或默认读取所有账号。
- 自动批准自己的成果，或用任务步骤完成代替目标达成。
- 外部动作结果不明确时无限重试或直接重做。
- 把无来源推测写成已经证实的事实。
- 首版复刻任一参考仓库的完整能力或视觉布局。

## 9. 第一条端到端闭环

### 9.1 样板任务

> 用户提供脑暴、参考项目和已有草案；Irixi 建立目标卡，整理材料，生成完整 PRD 候选稿，按目标独立核对并展示修改摘要；用户确认准确版本后，才导出正式 PRD。

### 9.2 标准流程

```text
收到任务与材料
  ↓
形成目标卡：最终成果、成功条件、边界、格式
  ↓
材料入账：来源、权限、解析状态、快照
  ↓
生成短计划：每一步都说明支持哪条成功条件
  ↓
按需执行：整理 → 起草 → 核对
  ↓
生成候选版本：正文、来源、修改摘要、检查结果
  ↓
用户修改 / 继续工作 / 确认准确版本
  ↓
确认导出动作的版本和位置
  ↓
生成正式文件与回执
```

### 9.3 减少确认疲劳的规则

- 用户输入已经明确包含成果、范围和格式时，不重复追问同一件事，直接显示目标卡并开始低风险工作。
- 支持当前目标的建议可进入计划，并在变更摘要中可见。
- 偏离建议进入“以后再看”，不打断当前主线。
- 只有目标替代、资料范围扩大、费用越界或跨越正式/外部边界时才必须停下确认。
- 确认绑定准确动作、对象和版本，不是一次性给 Irixi 永久高权限。

## 10. 状态机

### 10.1 任务状态

```text
已收到
→ 目标待明确 / 目标有效
→ 计划中
→ 执行中
→ 等待资料 / 等待用户 / 检查中
→ 候选成果就绪
→ 等待确认
→ 正式应用中
→ 完成 / 部分完成 / 失败 / 取消
```

### 10.2 产物状态

```text
草稿中 → 候选版 → 已确认正式版 → 被后续正式版替代
```

- 确认必须绑定准确版本，而不是只绑定文件名。
- 确认后继续修改会产生新的候选版，不继承旧确认。
- 新候选版出现时，旧正式版仍然有效。
- 写入失败或结果不明确时，不得把候选版标记为正式版。

### 10.3 专业角色状态

```text
未调用 / 准备中 / 读取资料 / 起草 / 核对 / 等待 / 完成 / 失败 / 已取消
```

办公室动画只能由这些真实状态驱动。

## 12. Agent 工作架构

### 12.1 角色模型

**Irixi 总管**是唯一对用户和最终成果负责的角色，职责包括：

- 维护当前目标和目标版本；
- 判断新信息与目标的关系；
- 拆分可检查工作项；
- 为专业能力分配有限材料、工具和输出位置；
- 汇总产物、触发核对、处理冲突；
- 向用户交付候选版本、未确定项和正式动作请求。

首版专业能力采用工作模式，不要求长期运行的独立人格：

- **资料整理**：建立材料清单，提取事实与未知项。
- **文档起草**：按目标、结构和材料生成候选内容。
- **独立审阅**：不沿用起草者的完成判断，检查目标符合度、缺项、证据和越界。

### 12.2 每次专业调用必须携带的 Agent Card

- 当前目标版本和不可改变的边界；
- 本次工作的唯一预期结果；
- 允许读取的材料；
- 允许使用的工具与输出位置；
- 必须停下确认的动作；
- 成功、失败、部分完成的判断标准；
- 超时、重试和恢复规则。

专业角色可以提出意见，但不能直接修改目标、扩大权限或把自己的输出标成正式成果。

### 12.3 防跑偏主链

```text
当前目标版本
  → 本版必须结果
    → 工作项
      → 当前动作
        → 产物与证据
```

每次准备执行下一步前，系统回答四个问题：

1. 当前有效目标是否仍然相同？
2. 当前动作具体支持哪条必须结果？
3. 上一步工具或专业角色实际返回了什么？
4. 下一步是否仍是推进目标的最小有效动作？

无法回答时不得继续装作正常推进。

## 13. 新建议与目标变更规则

| 关系 | 定义 | 默认行为 |
|---|---|---|
| 支持目标 | 最终成果和达成标准不变，只改善路线或质量 | 更新计划或工作项，记录理由，继续执行 |
| 替代目标 | 最终成果、受益者、范围或达成标准发生实质变化 | 暂停受影响步骤，展示旧版、新版、代价和未完成项，等待用户确认 |
| 偏离目标 | 可能有价值，但不推进当前成果 | 放入“以后再看”，继续主线 |
| 不明确 | 暂时无法判断是否推进目标 | 保持旧目标，仅询问一个会改变路线的关键问题或做最小验证 |

安全、法律、权利、成本或可行性问题可以阻止当前路线并发起目标重议，但不能悄悄换成更容易完成的结果。

用户始终可以纠正系统对建议关系的判断。纠正后，系统必须：

1. 保持纠正前的当前目标有效，除非用户同时明确接受了替代目标；
2. 重新计算受影响的工作项和下一步；
3. 停止与新分类冲突、但尚未发生的动作；
4. 保留原分类、纠正结果、操作者和时间。

首版需要一组固定防跑偏案例，至少覆盖支持、替代、偏离、不明确、局部扩大范围和建议与目标冲突。所有案例都必须保持正确目标版本，并按规则停止或继续。

## 14. 产物、来源与审阅

### 14.1 三类文件

- **工作材料**：用户提供的原始文件与只读资料。
- **候选成果**：Irixi 在隔离任务空间内新建的版本，可比较、可修改、可丢弃。
- **正式成果**：用户确认准确版本并批准导出后形成的文件。

### 14.2 候选版本必须包含

- 逻辑产物 ID 与版本号；
- 关联的目标版本；
- 使用的材料清单与快照；
- 本版修改摘要；
- 自动检查结果；
- 尚未核实的事实与限制；
- 创建时间与生成角色；
- 当前状态和是否被用户确认。

### 14.3 文档交付检查

“独立核对”指审阅运行只接收当前目标、允许使用的材料快照和候选成果，不继承起草者关于“已经完成”的判断，也不依赖起草者的隐藏推理。可以由独立审阅上下文与确定性文件检查共同完成。

1. **目标符合度**：内容是否直接满足目标和成功条件。
2. **结构完整性**：约定章节、结论和交付格式是否齐全。
3. **事实与来源**：事实是否有材料支持，推断是否被明确标记。
4. **边界检查**：是否擅自扩大范围、权限或承诺。
5. **版本检查**：展示的正文、差异和待确认动作是否指向同一准确版本。
6. **可用性检查**：文件能打开、内容非空、编码正确、链接与基本格式可用。

审阅必须逐项返回结果、证据和未通过原因。存在目标错误、关键缺项、无来源确定结论或越权内容时，候选稿不得进入“就绪”或“完成”状态。

## 15. 权限、安全与隐私

### 15.1 动作分级

| 动作 | 首版默认策略 |
|---|---|
| 读取用户本次明确选择的本地材料 | 允许，只读且限制在选择范围内 |
| 在 Irixi 任务空间分析、整理、起草和检查 | 允许 |
| 创建新的候选版本 | 允许 |
| 读取网址或通用网页搜索 | v0.1 不实现；后续必须由用户为任务或限定范围开启 |
| 把资料发送给已配置云模型 | 首次设置时说明提供方、发送范围和保留风险；在已同意范围内运行 |
| 切换到新的外部服务或扩大资料发送范围 | 必须确认 |
| 导出到用户指定的新文件 | 必须确认准确版本和目标位置 |
| 覆盖已有文件 | v0.1 不实现；未来必须展示差异和恢复方式后确认 |
| 删除 Irixi 本地任务数据 | v0.1 由用户在可见任务目录中自行处理；应用内可恢复删除列入 P1 |
| 发送、发布、提交表单、创建日程、删除来源或外部内容、付款、改权限 | v0.1 不实现；未来实现时必须动作级确认 |
| 执行模型生成的任意代码或 shell | 禁止 |

### 15.2 安全要求

- 工具采用允许清单和最小参数范围，不给专业角色继承更高权限。
- 不扫描用户未选择的目录、账号、历史记录或密钥。
- 外部网页、文档和邮件内容都作为不可信输入，不能通过其中的指令扩大权限或改目标。
- 密钥不写入聊天、产物、活动记录或长期记忆。
- 活动记录默认只持久化动作与结果摘要；原始工具输出按需临时查看，对个人资料和大段材料进行脱敏或截断。
- 正式和外部动作使用幂等标识；结果不明时先核查，不自动重试。
- 未来增加覆盖能力时，必须先创建可恢复副本，写入失败时保留旧正式版本。
- “本地优先”不等于虚假宣称“完全离线”；只要使用云模型或网络工具，就必须清楚显示哪些内容离开设备。

### 15.3 记忆边界

首版只保存任务内必要状态，不默认建立跨任务人物画像。跨任务偏好记忆以后单独设计，必须可查看、修改、导出和删除。

## 16. 页面与信息架构

产品长期采用“办公室总览 + 任务书桌”的双层体验。v0.1 先交付任务书桌和一只 Irixi 的真实状态指示；完整办公室总览在核心闭环通过后加入。

### 16.1 状态总览

用于快速回答：现在有没有任务、Irixi 在做什么、是否在等待我、是否失败、最新成果在哪里。v0.1 可以是工作台中的紧凑状态区，不要求可行走的完整房间。

必须显示：

- 当前活动任务与目标短句；
- 真实任务状态；
- 当前工作角色与工作项；
- 等待用户、失败和完成提示；
- 进入任务书桌的明确入口。

完整维多利亚办公室在 P1 中复用同一状态接口，不另建一套任务状态。

### 16.2 任务书桌

这是完成工作的主界面，不让用户必须在像素房间里寻找信息。固定包含：

1. **目标卡**：当前目标、成功条件、范围和版本。
2. **材料区**：材料清单、授权与解析状态。
3. **计划与活动**：当前步骤、真实结果和下一步。
4. **成果区**：候选正文、历史版本、差异和检查。
5. **待确认区**：需要用户作出的唯一或少量关键决定。

### 16.3 成果审阅

- 默认打开最新候选版。
- 可以切换历史版本并查看修改摘要或差异。
- 将“事实待核实”“范围变化”“正式动作”分开显示。
- 用户可继续修改、退回、保留候选、确认版本或取消任务。

### 16.4 设置

- 工作区位置与默认导出位置；
- 当前模型或服务提供方及资料边界；
- 网络读取权限；
- 任务数据查看；应用内可恢复删除在 P1 加入；
- 动画减弱、字号和声音设置。

首版具体采用桌面壳还是本地网页仍是开放问题，但上述信息架构不依赖包装方式。

## 17. 视觉与角色要求

### 17.1 已确认视觉方向

- 像素风维多利亚时代办公室、建筑和室内。
- Irixi 是唯一猫头鹰主角：人形猫头鹰绅士、礼帽、单片眼镜、手杖、墨绿燕尾服。
- 当前锁定阵容为“一位猫头鹰主角 + 多位不同小动物同事”，不再采用全员猫头鹰方案。
- 详细角色约束以 [`art/production-guides/cast-lock.md`](../../art/production-guides/cast-lock.md) 为准。

### 17.2 首版最小状态表现

至少可区分：

- 空闲；
- 阅读资料；
- 起草；
- 核对；
- 等待用户确认；
- 完成；
- 失败或受阻。

每种状态必须同时有文字或图标说明，不能只靠颜色和动画。用户选择减弱动画后，产品仍可完整使用。

### 17.3 视觉与执行的边界

- 角色数量不等于实际并发 Agent 数量。
- 小动物可以代表专业能力，但具体映射尚未确定。
- 没有真实任务时，角色只能显示空闲或环境状态，不得伪造办公活动。
- 完整办公室建造、行走协作和装饰系统不是首个业务闭环的发布条件。

## 18. 核心数据对象

| 对象 | 最少字段 |
|---|---|
| Task | ID、标题、所有者、当前目标版本、状态、创建与更新时间 |
| GoalVersion | 目标、成果、成功条件、边界、状态、前一版本、确认记录 |
| Material | 来源、类型、授权范围、快照、解析状态、使用关系 |
| WorkItem | 目标关联、预期结果、状态、负责角色、检查方法 |
| AgentRun | 角色、输入引用、工具范围、开始与结束、输出、状态 |
| ArtifactVersion | 逻辑 ID、版本、候选/正式状态、位置、差异、来源、检查 |
| Suggestion | 内容、与目标的关系、去向、处理理由 |
| Approval | 动作、对象、准确版本、影响、有效范围、决定、时间 |
| Evidence | 检查对象、检查方法、结果、时间、适用版本 |
| Event | 用户可读的真实动作、结果、来源和时间 |

这些对象构成唯一事实来源。办公室、任务书桌和恢复流程读取同一状态，不各自维护第二套真相。

## 19. 非功能要求

### 19.1 可恢复性

- 每次目标变化、候选版本产生、确认和正式动作前后都保存检查点。
- 应用异常关闭后，不丢失已保存的候选成果。
- 恢复时先读取目标，再读取未完成工作和旧的下一步建议。
- 未确认或结果不明的副作用不得在恢复后自动执行。

### 19.2 一致性与完整性

- 界面显示的目标版本、候选版本和确认对象必须一致。
- 工作台与办公室投影来自同一状态记录。
- 不能在缺少对应证据时宣称完成。

### 19.3 可理解性

- 用户无需查看技术日志，就能看到目标、当前状态、当前成果、未确定项和下一步。
- 长任务开始后立即显示已接收和当前步骤；只在真实状态变化时更新，不伪造百分比。
- 错误信息说明发生了什么、保留了什么、是否有外部影响和下一步选项。

### 19.4 隐私与可删除性

- 任务状态和候选文件默认保存在用户可控的本地工作区。
- 用户可以查看某任务使用了哪些材料和外部服务。
- 每个任务保存在用户可见的独立目录中，v0.1 可由用户通过系统文件管理器移入回收站；P1 再提供应用内可恢复删除。
- 删除 Irixi 任务目录不应连带删除来源材料或已经导出的正式文件。

### 19.5 可访问性

- 关键状态不只依赖色彩、音效或动画。
- 支持键盘完成创建任务、审阅、确认与取消主流程。
- 提供减弱动画选项。

## 20. 验收场景

### AC-01 从脑暴到 PRD

给定本次脑暴、两个参考项目的已保存材料摘要和已有 Irixi 草案，系统建立目标卡与材料账本，生成一份完整 PRD 候选稿；用户能看到使用的材料、修改摘要、检查结果和待确认项。

### AC-02 支持目标的建议

用户增加一个能改善 PRD 质量但不改变最终成果的建议。系统将其标为“支持目标”，更新对应工作项，并保持目标版本不变。

### AC-03 偏离目标的想法

用户或专业角色提出一个有价值但与当前 PRD 无关的功能。系统把它放入“以后再看”，主任务继续，不因新鲜想法改写首版范围。

### AC-04 替代目标

用户要求把最终成果从 PRD 改成可运行应用。系统展示旧目标、新目标、影响和未完成项，暂停会因目标替代而失效的当前动作，不启动只适用于新目标的动作；未确认前旧目标仍然有效。

### AC-05 中断恢复

执行中强制关闭并重新打开。当前目标、材料索引、候选版本、未完成项和待确认状态完整恢复，且不会重复导出或其他副作用。

### AC-06 正式动作保护

未确认时尝试导出正式版，动作被阻止并给出易懂说明。确认必须绑定准确版本和新的目标位置；目标路径已存在时 v0.1 拒绝覆盖。

### AC-07 工具失败

材料解析或生成过程失败。界面显示真实失败状态，已有候选稿仍可查看，并提供重试、跳过、换材料或取消选项。

### AC-08 来源不足

材料不能支持某项事实。候选成果将它标为待核实或推断，不把它写成确定事实；审阅检查可定位该位置。

### AC-09 新候选版不继承旧确认

用户已确认 v1 后又要求修改。系统创建 v2 候选版，v1 仍保持正式；只有再次确认 v2 后，v2 才能成为新正式版。

### AC-10 状态投影一致

角色显示“等待确认”“完成”或“失败”时，任务状态和实际证据一致。断线或后端失败时不得继续显示正在工作或已经完成。

### AC-11 防跑偏固定案例集

对支持、替代、偏离、不明确、局部扩大范围和建议与目标冲突六类固定案例运行测试。每个案例都保持正确目标版本；需要替代确认的动作在确认前停止，用户纠正分类后计划被重算且留有记录。六类案例必须全部通过。

### AC-12 独立审阅阻断

起草结果故意缺少一条成功条件或包含一项无来源确定结论。独立审阅只依据目标、材料快照和候选稿发现问题，给出对应证据，并阻止该版本被标记为就绪或完成。

## 21. MVP 成功指标

先使用 5 个用户本人的真实“材料到文档”任务进行个人试用。以下为推荐试验门槛，尚待用户确认：

| 指标 | 推荐门槛 |
|---|---|
| 成果可用率 | 至少 4/5 个任务在不超过两轮主要修改后被用户接受 |
| 静默目标变化 | 0 次；所有替代目标均有用户确认的新版记录 |
| 防跑偏案例 | 固定六类案例 100% 通过；用户纠正分类后计划和记录正确更新 |
| 未授权正式或外部动作 | 0 次 |
| 恢复正确率 | 3/3 次中断测试恢复正确目标、版本和待确认状态 |
| 来源与版本完整度 | 5/5 个最终候选可追溯到目标版本和材料清单 |
| 状态真实性 | v0.1 中工作台、后台记录与 Irixi 状态指示一致；P1 加入办公室后继续保持一致 |
| 用户负担 | 用户主观确认较当前做法减少重复说明、资料衔接或校对负担 |

“主要修改”指改变核心结论、范围、成功条件，或新增、删除、重写一个顶层章节；错别字和局部措辞不计入。每个试用任务开始前，用户记录现有做法的大致耗时、人工步骤和纠偏次数，完成后再用同一口径对比负担。

不使用“Agent 运行时长”“角色活动次数”“生成字数”作为成功指标。

## 22. 发布与验证门槛

### 22.1 v0.1 Alpha 个人试用门槛

只有同时满足以下条件，版本才可以交给用户开始个人试用：

- IRX-P0-01 至 IRX-P0-14 均有可重复验证证据。
- AC-01 至 AC-12 全部通过。
- 至少一条真实材料到文档任务从输入走到正式导出。
- 没有已知的未经确认写入、越权读取、敏感信息泄露或任意代码执行路径。
- 中断恢复测试通过，结果不明的动作不会自动重试。
- Irixi 状态指示与真实任务状态一致，动画关闭后主流程仍可完成。
- 所有第三方代码和素材都有可追溯来源与许可记录。

目标版本、防跑偏、恢复、正式动作保护、数据边界和状态真实性属于不可豁免门槛，不能用用户接受例外代替测试通过。

### 22.2 v0.1 MVP 验证成功门槛

Alpha 交给用户后，还必须满足以下条件，才能称为 MVP 验证成功：

- 由实际运行的 Irixi 完成 5 个用户真实任务，回放夹具不计入。
- 第 21 节的推荐指标经过用户确认，并达到 4/5 成果可用率、0 次静默目标变化、0 次未授权正式动作和 3/3 恢复正确率。
- 试用中发现的目标控制、数据边界、恢复、确认保护和状态真实性缺陷已经修复并重新通过相关案例。
- 用户确认产品确实减少了重复说明、资料衔接或校对负担；若没有，则回到问题与范围重新判断，而不是宣布成功。

### M1：无外部副作用的文档闭环

- 目标卡、材料账本、计划、候选 Markdown、核对与版本历史可用。
- 先以任务书桌完成全流程。
- 提供最小 Irixi 状态角色，不建设完整办公室。

### M2：正式版本与恢复闭环

- 精确版本确认、正式导出、恢复、副作用保护和活动记录可用。
- AC-01 至 AC-12 全部通过，达到 v0.1 Alpha 个人试用门槛。

### M3：个人试用

- 由实际运行的 Irixi 完成 5 个真实材料到文档任务；产品出现前生成的本 PRD 只作回放夹具，不计入通过数。
- 达到第 22.2 节门槛后，v0.1 才能称为 MVP 验证成功。

### M4：v0.2 视觉与能力扩展

- 把实际任务状态映射到已确认的完整维多利亚办公室与多位角色，不增加新的执行真相来源。
- 只加入 M3 真实使用数据支持的下一类材料、输出或连接能力。

## 24. 主要风险与应对

| 风险 | 早期信号 | 应对 |
|---|---|---|
| 范围膨胀成万能办公平台 | 首条闭环未通过就开始做邮箱、日历、表格 | Later 只能由真实触发证据升级；当前目标不变 |
| 多 Agent 变成表演 | 角色很多，但产物和检查没有增加 | 一个负责人；专业能力按需调用；活动必须绑定工作项 |
| 视觉投入吞噬核心闭环 | 大量时间用于房间和动画，候选成果仍不可用 | M1 只做最小状态角色；完整办公室在闭环通过后接入 |
| 目标锁定过于僵硬 | 用户发现原目标错误却难以修正 | 支持显式目标替代版本，不把“目标优先”做成永不允许改 |
| 确认过多导致体验拖沓 | 用户频繁点击但风险并未变化 | 低风险候选空间连续工作；仅在范围、目标、费用和正式边界确认 |
| 模型幻觉或材料误读 | 文档出现无来源确定结论 | 材料快照、来源检查、待核实标记、独立审阅 |
| 外部动作重复 | 超时后系统再次写入或发送 | 幂等标识、先核查结果、不确定时停下 |
| 云模型隐私不透明 | 用户不知道哪些内容离开设备 | 首次设置说明提供方和范围；运行中显示当前数据边界 |
| 参考代码带入安全与许可问题 | 为省时直接复制执行器或素材 | 逐项审计；默认重写安全边界；保留来源与许可 |
| 账本和界面出现两套状态 | 角色显示完成但成果未通过 | 单一状态源；每个显示状态都有后端条件和测试 |

## 25. 开放决定与推荐默认值

这些是进入实现前仍需用户确认的产品决定。为了避免下一步停滞，给出推荐默认值：

| 决定 | 推荐默认值 | 理由 |
|---|---|---|
| 第一条正式闭环 | 材料到可交付文档，并先做 PRD/方案 | 高频、低权限、可直接验收，也能验证全部核心机制 |
| 第一版入口 | 本机运行的桌面式工作台；首个实现可采用本地网页界面 | 保留桌面体验，同时降低首版包装成本 |
| 首版输入 | 粘贴文本、MD/TXT；PDF/DOCX/URL 进入 v0.2 | 先验证核心闭环，避免格式解析和网络权限同时扩大范围 |
| 首版输出 | Markdown 候选与正式文件 | 版本和差异易处理；Word/PDF 高保真导出延后 |
| 网络能力 | v0.1 不直接联网；v0.2 再加入明确 URL 和按任务开启的搜索 | 让首个闭环在最小数据边界内可重复测试 |
| 模型路线 | 先使用用户现有可用模型，清楚显示提供方和资料边界 | 先验证工作闭环，不把本地模型工程当首版前置条件 |
| 视觉交付 | v0.1 只有一只 Irixi 的真实状态指示；完整办公室在业务闭环通过后接入 | 保留产品辨识度，避免视觉反客为主 |
| 小动物角色映射 | 暂不固定为具体 Agent 能力 | 先用真实工作验证能力分工，再决定视觉映射 |
| 并发策略 | 可保存多个历史任务，同一时间只执行一个活动任务 | 降低状态、权限、成本和恢复复杂度 |

## 26. 本 PRD 的确认含义

用户确认本 PRD 作为产品基线后，表示：

- 接受“目标锁定的个人办公成果工作台”作为第一阶段产品定位；
- 接受“材料到可交付文档”作为首条闭环；
- 接受 Must、Later、Won't 和目标防跑偏规则；
- 同意下一步基于此 PRD 形成可验收规格和实施计划。

除本节已经明确列出的产品定位与首条闭环外，第 25 节中的开放决定只有在用户逐项确认或明确表示“接受全部推荐默认值”后才成为已接受决定；没有被点名的项目继续保持待定。

确认本 PRD **不等于**授权把资料发送给云模型，也不等于授权发送、发布、覆盖用户正式文件、安装依赖、部署或连接外部账号。云模型的数据边界必须在第一次真实使用前单独、可见地确认；其他动作仍按各自边界处理。

## 附录 A：关键术语

- **目标卡**：用户可读、可版本化的最终成果、成功条件与边界。
- **候选成果**：Irixi 可以继续修改、用户尚未确认正式应用的版本。
- **正式成果**：用户确认准确版本并批准正式动作后形成的结果。
- **目标替代**：最终成果或达成标准发生实质变化，而不只是实现方式调整。
- **状态投影**：把真实任务状态显示成工作台信息和办公室角色动作，不产生新的执行事实。
- **专业能力**：按需执行资料整理、写作、审阅等工作的受限模式，不自动拥有独立目标或更高权限。
