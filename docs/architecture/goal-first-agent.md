# Irixi 目标优先工作架构

> 本文件是机制与证据说明，不是第二份行动纲领。项目建设的长期目的、当前阶段、权限、变更与验收规则以根目录 [AGENTS.md](../../AGENTS.md) 为唯一权威入口，最新明确用户指令优先。历史DZ记录保留但当前暂停；已发布/已完成的历史表述不能替代当前运行证据。

## 运行时如何保存当前目标

任务记录保存目标、成功条件、边界及其版本，工作项绑定目标及材料/交代输入指纹；候选/审阅/确认校验目标与项目交代、原生文件哈希，但目前不绑定或重验材料集合。材料变更后的旧成果新鲜度也是实际缺口。讨论回复只保存为带范围的对话；替换建议与明确接受是不同动作。接受新版完整目标卡后旧活动工作失效、关联任务被协调并在写回前再次核对根版本；旧成果保留为历史，不能作为新版正式交付。

显式关联注入根目标、已接受交代和相关任务摘要。根输入指纹目前只含根目标版本与有效交代ID；不包含根材料，也不复制根材料正文。材料仍按每个任务明确加入/授权；目标变更后本任务的全部ready材料仍可提供给模型，尚未实现按目标版本隔离或适用性确认。这是与长期目的的实际差距，不能用“记忆/关联已连通”掩盖。

AGENTS供建设代理读取；产品Codex子进程使用ignore-rules且关闭自带shell/浏览器/应用/插件，所以运行时规则落实来自宿主代码与任务记录，不来自AGENTS文件自动执行。语义对齐和审阅包含模型判断，硬守卫只保证版本、范围、结构、预算和确认条件。

## 工作编排层

一次办公任务按以下状态前进：

```text
收到任务 → 明确目标 → 制定可检查的步骤 → 执行与观察
→ 生成候选成果 → 自检与独立核对 → 等待用户确认
→ 正式应用或保留候选稿 → 完成 / 部分完成 / 失败 / 取消
```

每轮继续前检查四件事：当前目标有没有变、当前步骤支持哪条必须结果、工具实际返回了什么、下一步是否仍是最小且有效的动作。中途回答问题后，系统回到尚未完成的主链，而不是把最新话题当成新任务。

## Agent 组织方式

当前采用“一个负责人，按目标按需组建任务团队”的方式：

- 负责人保存目标、拆分工作、控制版本并向用户交付。
- 研究、写作、表格、文档、审阅等角色只在任务需要时出现。
- 专业角色可以提出意见，但无权自行改变最终目标。
- 多个角色的输出必须回到同一份任务记录和产物链，不各自维护互相冲突的真相。
- 没有实际工作时，不持续调用模型。角色可以播放低开销的本地休闲动画；任务、进度与工作状态仍须反映实际记录。

真实模型先返回经结构校验的 DAG，系统再为本任务建立临时角色、工作项和可恢复会话。只有依赖满足的工作项可以进入运行；独立分支可并行，但模型调用数、工具往返、重规划次数和总运行时间都有上限。规划器、执行者、审阅者和交付角色不能用同一角色自审；工作结果、工具记录与会话都写回同一任务文件。

这保留了两个参考项目中“办公室团队、角色分工、状态可视化”的价值，同时避免把角色活动本身误当成生产力。

## 产物与版本层

Irixi 区分三种东西：

- 工作材料：用户提供的原始文件和只读资料。
- 候选成果：Agent 新生成或修改的版本，可比较、可回退、可继续编辑。
- 正式成果：用户明确确认后，才写入指定位置或触发指定外部动作的版本。

每个成果保留来源、目标版本、修改摘要、检查结果和确认状态。默认不在原件上直接覆盖。

## 当前权限机制

权限规范统一见[AGENTS.md](../../AGENTS.md)。目前宿主只执行模型计划预声明的六类工具；Codex子进程关闭其自带执行能力。成果通过独立核对且指定版本确认后可下载新文件，不覆盖源文件。发送、发布、付款、删除、线上日程与任意工作区变更当前没有实现；未来接入须另定义并确认对应授权及验收。

## 状态投影与维多利亚办公室

办公室视图呈现实际执行状态，例如查阅资料、整理草稿、等待确认、检查失败和交付完成。空闲时可以用本地规则播放走动、休息等装饰动画，不触发模型调用，也不产生任务进展。工作状态优先，断线、失败或等待用户时必须显示对应文字，装饰动画不能掩盖停滞。

视觉设定保持为维多利亚时代的人形猫头鹰绅士、礼帽、手杖、单片眼镜及同时期办公室。美术资产在独立任务中维护，不反向改变核心工作流。

## 与项目建设工作流的关系

Irixi 的产品运行时自行保存用户任务、目标版本、材料、工作项、会话、候选成果、审阅和确认状态。项目所有者当前已暂停 DZ 建设工作流；运行时不依赖 DZ，也不会写入 DZ 记录。本节只说明当前边界，不建立替代进度账本。

## 当前实现与验证边界

2026-10-01 的持续项目助手增量已落入现有任务记录：完整目标卡一起确认并保留版本；明确关联的任务接收根目标、有效交代和必要摘要；根输入改变时暂停旧工作，并在接收结果、审阅和导出前重新核对实际根输入。跨任务修改在同一存储队列内串行处理，各文件原子保存，重启再协调项目输入；这不是跨文件数据库事务。

“继续工作”根据有效记录选择重新规划、继续执行、等待决定或明确停止。续接面板从已完成工作、当前候选、失败及待决定事件派生“已经做成、尚未完成、为什么停下、下一步”。对话历史绑定目标、项目输入和交代，旧结果保留为历史，不作为当前结论。有效工作缺口进入既有有限重规划，重复同错、权限错误和预算耗尽保持停止。

主控以隔离数据运行真实规划、材料读取、清单写作、独立审阅、跨角色与重启续接，实际检验完整目标变更和冲突停下，并核对可编辑 Word 的三页预览与浏览器下载哈希。主控收紧过两句验收表述，再由真实独立审阅通过，因此不能把该样例称为全程无人干预写作。合法缺口自动修复、迟到结果拒收和并发传播的完整分支以受控提供者回归为证；未宣称每个分支都有真实模型现场证据。详见 [持续项目助手增量验收](../evidence/acceptance-continuity-20261001.md)。

当前能力仍限于明确权限、预算和现有工具支持的办公项目。任务关联需要明确指定；语义冲突识别依赖模型，不能保证识别所有矛盾；用户仍决定目标替换、冲突取舍及指定成果确认。长期无人值守可靠性、自动发现跨项目关系、自改代码、任意工具和新的外部动作尚未获本轮验收。

当前已实现动态计划与任务团队、持久化会话、材料/记忆/计算/公开网页白名单工具、候选版本、独立审阅、确认门，以及可编辑 DOCX/XLSX/PPTX 的候选生成与渲染检查。公开网页读取可在安全校验后保存为任务材料；搜索发现的 URL 必须再次读取正文才能成为可引用证据。普通无密钥网页搜索在当前网络出口遇到站点验证时，可在预算预留后使用专用只读 hosted-search 发现候选 URL；它不读取任务材料，也不能代替原站正文读取。子进程、账户、契约或超时异常均明确失败，不会生成伪引用。

真实采购任务已验证研究、写作、独立审阅、修改与复核链，以及含公式的多工作表 XLSX 和中文 DOCX。真实会议任务曾暴露旧候选中的阶段状态污染与宽表排版问题；修复后已用新的真实模型运行重新生成、独立审阅并由用户确认 DOCX 与恰好 4 页的 PPTX，且从 UI 下载文件与已审阅成果哈希一致。该证据只覆盖当前会议样例和通用办公版式，不扩大为品牌级排版精修或全部任务类型的验收。

## 2026-09-21 用户取舍修正

历史依据：用户当时允许不消耗模型Token的空闲活动、必要团队扩张和家具布局编辑，并要求评估现成代码与最小实现。以下记录当时办公阶段的取舍；长期目的及后续改变以AGENTS为准。下表同时标出后来已经落地的部分与仍未完成的部分。

| 事项 | 用户已明确的方向 | 实现判断与边界 |
|---|---|---|
| 空闲活动 | 无事时可以活动，有事时执行任务；不应为活动消耗模型 Token | 采用本地动画/规则，工作可立即打断。动画仍消耗 CPU/GPU、电量，不能承诺零资源；建议页面隐藏时暂停并支持关闭。 |
| 团队扩张 | 目标模式下，为完成目标确有必要时可以扩张 | 已实现任务限定的临时角色、DAG、并发与预算上限。角色仍共享同一模型能力，增加角色不等于增加知识或权限。 |
| 家具布局 | 允许家具布局编辑，不再一概排除 | 已拆分部分家具并支持一件家具位置的合法保存/恢复；完整布局编辑器尚未实现。 |
| 代码复用 | 可以直接使用合适的现成代码，减少编程和 Token 开销 | 比较复用、适配、自写的总成本，使用最省事且满足目标的方式。不能把潜在风险当作一概重写的理由，也不能宣称复用必定更便宜。 |

成本区分：开发时的阅读、改造、调试和测试消耗，与产品运行时的模型调用量分别计算。复制或复用代码本身不会降低每次任务的模型消耗；减少重复上下文和不必要调用才可能降低运行 Token。零依赖、全原创、Agent 数量和动画丰富度均不作为成功标准。

两个项目根许可证均为 MIT，已按实际选用文件保留声明。当前选择是有界适配：OpenOffice 固定版本 `retry.ts` 的尝试计数、可重试上限与前 80 字符同错判定已适配进 Irixi 的持久化执行状态；`phase-machine.ts`、`delegation.ts` 和 `types.ts` 只作为阶段、委派和结果批次语义参考。没有接入其 AgentManager、AgentSession、worker、worktree、merge、模型运行或预览服务。agent-office 实际适配了 Phaser/EasyStar 场景与网格思路，以及 `ToolExecutor` 里的 DuckDuckGo 无密钥搜索回退。Irixi 自己实现目标、任务账本、动态计划、模型会话、安全网页读取、原生文件、审阅与确认门。这一选择为了减少无关运行时和维护面，不代表已证明所有复用都比自写更省。

当前代码实况：`app/orchestration.mjs` 校验模型计划、团队、DAG 与受控工具；`app/server.mjs` 执行并持久化会话、结果批次、原生候选和独立审阅；`app/public/office-game.js` 按美术清单加载房间、角色和独立家具。办公室状态是任务记录的投影；它不是自主运行的第二套 Agent 系统，完整家具编辑器也仍未实现。

## 开源评估证据的角色

复用规则统一见[AGENTS.md](../../AGENTS.md)，下节只记录已完成检索增量及MiniSearch对照。历史候选评估是探索记录，不是新的产品目标或已批准的接入规格；未实施的Readability、MarkItDown、Codex SDK等方向不得据此自动接入。

## 2026-10-02 检索改进落地

已安装材料与已确认记忆的局部检索改进。中文使用Node自带`Intl.Segmenter`，英文和数字支持短条件；先按词覆盖与精确短语等简单规则排序，再应用结果上限。引用返回命中的原文窗口、行号和字符范围，长文末尾及超长单行可以定位；仅标题命中每材料至多一条并明确标注。片段每项1000字符，材料结果数组约24k字符、记忆约18k字符，截断和继续核对的条件如实返回。

已确认记忆仍由有效记忆条目决定资格。当条目的任务、成果和版本来源完整一致，且对应成果为已确认或历史正式版本时，检索回到该版本完整原文，补上记忆保存前20k以外的内容；不改变记忆记录结构。候选、错误绑定或缺版本不能提升全文，撤回条目继续遮蔽原成果。同名不同全文冲突在查询匹配及结果截断前按全部合格来源判断，因此不命中查询的同名版本也不会被隐藏。

MiniSearch固定版7.2.0以相同中文分词，分别对照词频/长度、后置强相关材料和中文组合词三个小样例；预期项均与原生方案同排第一。当前未观察到足够接入收益，本轮采用原生能力与局部简单排序，未增加依赖、服务、模型调用或持久化索引。这只支持当前小样例下的取舍，不证明原生搜索在所有资料规模和问题上优于MiniSearch。

安装仅涉及`app/tools.mjs`及相关回归测试。主控通过实际`runAuthorizedTools`路径及真实本地确认函数检验长文、原文位置、权限、撤回、绑定和冲突，独立终审通过，安装后原任务字节不变且历史已确认Markdown仍可下载。详细证据见[检索改进验收](../evidence/acceptance-search-20261002.md)。本轮没有运行新的办公模型任务，没有测得真实Token节省比例；它提高了送入模型片段的相关性与可核对性，不能代替跨会话目标状态或独立审阅。
