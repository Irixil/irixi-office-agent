# Irixi 目标优先工作架构

> 状态：产品架构草案。它说明系统怎样防止跑偏，不代表具体功能、技术栈或首个办公任务已经确认。

## 一条不可颠倒的主链

```text
最终目标 → 本版必须结果 → 当前工作项 → 下一步动作 → 产物与证据
```

后面的任何一项都不能反过来重写前面的内容。模型、工具、角色、办公室场景和技术方案只是手段。某个步骤做完，不等于最终目标已经达成。

## 目标控制层

每个任务都有一条用户可读的目标锚点、达成条件和明确限制。它们形成当前有效版本，并保留历史。

新信息或建议进入系统后，必须先判断与当前目标的关系：

| 关系 | 含义 | 默认处理 |
|---|---|---|
| 支持目标 | 最终结果不变，只改善实现方式或质量 | 进入对应要求、计划或工作项 |
| 替代目标 | 受益者、最终结果或达成标准改变 | 同时展示旧目标和新目标，等待明确确认 |
| 偏离目标 | 可能有价值，但不推进当前结果 | 放入以后再看，继续当前主线 |
| 尚不明确 | 暂时无法判断是否推进目标 | 保持旧目标，先问一个关键问题或做最小验证 |

安全、合规、权利、成本和可行性检查可以暂停工作或建议换目标，但不能静默把任务改成更容易交付的东西。

## 工作编排层

一次办公任务按以下状态前进：

```text
收到任务 → 明确目标 → 制定可检查的步骤 → 执行与观察
→ 生成候选成果 → 自检与独立核对 → 等待用户确认
→ 正式应用或保留候选稿 → 完成 / 部分完成 / 失败 / 取消
```

每轮继续前检查四件事：当前目标有没有变、当前步骤支持哪条必须结果、工具实际返回了什么、下一步是否仍是最小且有效的动作。中途回答问题后，系统回到尚未完成的主链，而不是把最新话题当成新任务。

## Agent 组织方式

第一阶段采用“一个负责人，按需调用专业角色”的方式：

- 负责人保存目标、拆分工作、控制版本并向用户交付。
- 研究、写作、表格、文档、审阅等角色只在任务需要时出现。
- 专业角色可以提出意见，但无权自行改变最终目标。
- 多个角色的输出必须回到同一份任务记录和产物链，不各自维护互相冲突的真相。
- 没有实际工作时，角色不需要持续运行；办公室画面只投影真实状态。

这保留了两个参考项目中“办公室团队、角色分工、状态可视化”的价值，同时避免把角色活动本身误当成生产力。

## 产物与版本层

Irixi 区分三种东西：

- 工作材料：用户提供的原始文件和只读资料。
- 候选成果：Agent 新生成或修改的版本，可比较、可回退、可继续编辑。
- 正式成果：用户明确确认后，才写入指定位置或触发指定外部动作的版本。

每个成果保留来源、目标版本、修改摘要、检查结果和确认状态。默认不在原件上直接覆盖。

## 权限与动作层

- 默认可连续进行：读取已授权资料、分析、搜索、整理、计算、起草、在隔离空间生成新版本、执行无副作用的检查。
- 必须确认：覆盖正式文件、发送、发布、提交表单、创建日程、删除、付款、修改权限、进入生产环境或其他会影响外部世界的动作。
- 确认只对明确的动作、对象、版本和时间有效；失败、超时或重试必须避免重复副作用，并返回可见结果。

这就是“先生成一版供确认，再并入正式结果”的准确含义。不是每个字符修改都要逐次询问，而是在候选空间里允许连续工作，在跨过正式边界时确认一次清楚的变更。

## 状态投影与维多利亚办公室

办公室视图是执行状态的投影层，不是执行引擎。猫头鹰绅士的位置与动作只能由真实任务状态驱动，例如查阅资料、整理草稿、等待确认、检查失败和交付完成。断线、失败或等待用户时必须显示真实状态，不能继续播放“忙碌”来掩盖停滞。

视觉设定保持为维多利亚时代的人形猫头鹰绅士、礼帽、手杖、单片眼镜及同时期办公室。美术资产在独立任务中维护，不反向改变核心工作流。

## 与 DZ 的关系

Irixi 复用 DZ 的结构思想：明确意图、确认本版边界、形成计划、留下连续状态、绑定证据、支持恢复与交接。Irixi 额外把目标锚点放在所有建议和动作之前，并在恢复时先读目标、再读保存的下一步。

DZ 为产品建设过程提供治理；Irixi 的运行时把同一原则应用到日常办公任务。两者共享目标优先规则，但分别保存自己的项目状态和用户任务状态。

## 第一阶段仍待决定的唯一核心问题

在进入功能规格和技术实现前，需要选定一个真实办公任务作为第一条端到端闭环。它应当高频、材料可获得、结果好坏容易判断，并且可以在不获得过宽权限的情况下完成。
